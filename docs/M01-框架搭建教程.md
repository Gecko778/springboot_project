## 2. 生成工程

在项目根目录执行：

```bash
curl -G https://start.spring.io/starter.zip \
  -d type=maven-project \
  -d language=java \
  -d bootVersion=4.1.2 \
  -d javaVersion=21 \
  -d groupId=com.example \
  -d artifactId=ticket \
  -d name=ticket \
  -d packageName=com.example.ticket \
  -d packaging=jar \
  -d dependencies=web,thymeleaf,validation,security,actuator,devtools \
  -o ticket.zip

unzip -q ticket.zip -d .
rm ticket.zip
```

参数含义：

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `type` | `maven-project` | Maven 工程，不是 Gradle |
| `bootVersion` | `4.1.2` | 和项目冻结的 Spring Boot 4.1.x 对齐 |
| `javaVersion` | `21` | 项目基线 |
| `groupId` / `artifactId` | `com.example` / `ticket` | Maven 坐标 |
| `packageName` | `com.example.ticket` | 启动类所在包 |
| `dependencies` | 见下 | 只勾 M01 需要的 |

六个依赖分别在做什么：

| 依赖 id | 带来什么 | M01 里用在哪 |
| --- | --- | --- |
| `web` | Spring MVC + 内嵌 Tomcat | 启动 Web 容器 |
| `thymeleaf` | 服务端模板引擎 | M04 写页面 |
| `validation` | Bean Validation（`@NotBlank` 等） | M05/M07 表单校验 |
| `security` | 认证与授权 | M05 换成数据库用户；现在提供默认保护 |
| `actuator` | `/actuator/*` 运维端点 | 健康检查 |
| `devtools` | 改代码后自动重启 | 开发期省手工重启 |

**为什么这次不勾 MySQL、Flyway、Testcontainers？**

- `flyway`（它带的 `spring-boot-starter-flyway` 会引入 JDBC）加上 `mysql` 驱动后，JDBC 自动配置会启动。没有 `spring.datasource.url` 时，应用会在启动阶段直接报 `Failed to configure a DataSource`，连健康检查都看不到。
- `testcontainers` 会让 `./mvnw test` 依赖 Docker，和 M01 的目标冲突。

这些依赖在 M02（数据库）、M03（MyBatis）、M10（集成测试）再按需加回来。

生成后应该看到：

```text
HELP.md   mvnw   mvnw.cmd   pom.xml   src
```

确认版本：

```bash
grep -A2 'spring-boot-starter-parent' pom.xml
# <version>4.1.2</version>
```

**检查点**：`pom.xml` 里父工程是 `4.1.2`，`src/` 存在。

## 4. 把配置改成 YAML

项目后续统一用 `application.yaml`，先改名：

```bash
mv src/main/resources/application.properties \
   src/main/resources/application.yaml
```

**整份覆盖**成下面内容。不要用“在文件末尾追加”的方式写，否则原来的 properties 行会留在第一行，启动时报 `mapping values are not allowed here`：

```bash
cat > src/main/resources/application.yaml <<'EOF'
spring:
  application:
    name: ticket

server:
  port: 8080

management:
  endpoints:
    web:
      exposure:
        include: health
EOF
```

> 手动编辑也可以，但第一行必须是 `spring:`。改名后文件里原本有一行 `spring.application.name=ticket`，要删掉。

每一段的意思：

- `spring.application.name`：应用名，启动日志里的 `[ticket]` 就是它，后面 Micrometer 指标也会用它；
- `server.port`：HTTP 端口。默认就是 8080，写出来是为了后面改端口时不用查文档；
- `management...include: health`：只暴露健康检查端点。health 默认就暴露，这里写明确，避免以后加了别的端点却不知道暴露了什么。

**现在不要写 `spring.datasource`。** 数据源、MyBatis、Flyway 的配置统一在 M02 加；提前写会连不上库。

YAML 两个硬规则：

1. 缩进用空格，**不能用 Tab**；
2. 冒号后面有一个空格，例如 `name: ticket`，不是 `name:ticket`。

**检查点**：

```bash
cat src/main/resources/application.yaml
head -1 src/main/resources/application.yaml   # 必须是 spring:
```

文件里没有 `datasource`、`mybatis`、`flyway`，也没有 `spring.application.name=ticket` 这种 properties 写法。

## 5. 第一次启动

```bash
./mvnw spring-boot:run
```

首次会下载依赖，2–5 分钟。启动成功后，日志里应该有：

```text
Tomcat started on port 8080 (http) with context path '/'
Started TicketApplication in 0.6 seconds (process running for 0.7)
```

这两条说明：内嵌 Tomcat 监听 8080，Spring 容器初始化完成。启动耗时和线程名会因机器而异，认关键词即可。

### 5.1 两个“预期内”的警告

启动日志里大概率会有下面两条，它们不是故障：

| 日志 | 原因 | 什么时候消失 |
| --- | --- | --- |
| `Cannot find template location: classpath:/templates/` | 还没有 `src/main/resources/templates/`，Thymeleaf 找不到模板目录 | M04 建了模板目录后 |
| `Using generated security password: ...` | `spring-boot-starter-security` 没配用户时，自动生成一个内存用户 | M05 换成数据库用户后 |

判断标准：**出现 `APPLICATION FAILED TO START` 或 `ERROR` 才是失败**，`WARN` 先读一遍再决定。

停止应用：`Ctrl+C`。

> `devtools` 会让日志里的线程名显示 `restartedMain`，并且改代码后自动重启。这是正常的，不是重复启动。

## 6. 验收

保持应用运行，另开一个终端。

### 6.1 健康检查

```bash
curl -s http://localhost:8080/actuator/health
```

期望：

```json
{"groups":["liveness","readiness"],"status":"UP"}
```

Spring Boot 4 的响应里会多出 `groups`（存活/就绪分组），核心契约是 `status` 为 `UP`。也可以看状态码：

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8080/actuator/health
# 200
```

对应测试计划里的 **T01-1**。

### 6.2 默认安全行为

M01 还没有任何 Controller，但安全过滤器会在 DispatcherServlet 之前拦截请求。用 curl 访问 `/tickets`：

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8080/tickets
# 401
```

带上浏览器的 `Accept` 头，行为会变成跳登录页：

```bash
curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' \
  -H 'Accept: text/html' http://localhost:8080/tickets
# 302 http://localhost:8080/login
```

登录页本身是可访问的：

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8080/login
# 200
```

解释：

- 401 是默认安全配置对 curl（`Accept: */*`）返回的 Basic 认证挑战；
- 302 是同一套配置对浏览器返回的表单登录跳转；
- 两种都不是 M01 的 bug。M05 会自己声明 `SecurityFilterChain`，把入口统一到 `/login`。

> **和冒烟脚本的差异**：`scripts/smoke.sh --only=health` 除了健康检查，还断言未登录访问 `/tickets` 返回 302。M01 用 curl 实际是 401，所以这个脚本在 M01 阶段不会全绿。M01 的验收用 §6.1 和 §6.4；脚本等 M05 配好表单登录后再跑。`04-progress.md` 已同步这一点。

### 6.3 启动日志无 ERROR

如果想让日志同时落盘，先停掉 §5 的应用，再重新启动：

```bash
./mvnw spring-boot:run 2>&1 | tee /tmp/m01.log
```

另开终端检查：

```bash
grep -n 'ERROR' /tmp/m01.log
# 应该没有输出
```

对应测试计划里的 **T01-2**。

### 6.4 把验收变成自动化测试

新建 `src/test/java/com/example/ticket/HealthTest.java`：

```java
package com.example.ticket;

import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.boot.webmvc.test.autoconfigure.AutoConfigureMockMvc;
import org.springframework.test.web.servlet.MockMvc;

import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.jsonPath;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;

@SpringBootTest
@AutoConfigureMockMvc
class HealthTest {

    @Autowired
    MockMvc mvc;

    @Test
    void healthIsUp() throws Exception {
        mvc.perform(get("/actuator/health"))
                .andExpect(status().isOk())
                .andExpect(jsonPath("$.status").value("UP"));
    }
}
```

三个注解/类的作用：

- `@SpringBootTest`：起完整 Spring 容器，不是只测一个类；
- `@AutoConfigureMockMvc`：给测试注入 `MockMvc`，不用真的监听端口；
- `jsonPath("$.status")`：直接断言 JSON 字段，比字符串匹配稳。

> **包名注意**：Boot 4.1 的 `AutoConfigureMockMvc` 在 `org.springframework.boot.webmvc.test.autoconfigure`。2023 年前后的教程写的是 `org.springframework.boot.test.autoconfigure.web.servlet`，那是 Boot 3 的包，别照抄。如果 IDE 提示别的包，以 IDE 对当前依赖解析出来的为准。

运行：

```bash
./mvnw test
```

期望：

```text
[INFO] Tests run: 1, Failures: 0, Errors: 0, Skipped: 0 -- in com.example.ticket.HealthTest
[INFO] Tests run: 1, Failures: 0, Errors: 0, Skipped: 0 -- in com.example.ticket.TicketApplicationTests
[INFO] Tests run: 2, Failures: 0, Errors: 0, Skipped: 0
[INFO] BUILD SUCCESS
```

两个测试：一个是你写的 `HealthTest`，一个是生成的 `TicketApplicationTests#contextLoads`。测试不需要 Docker，也不需要数据库。

## 9. 卡住怎么办

| 现象 | 大概率原因 | 处理 |
| --- | --- | --- |
| `Failed to configure a DataSource: 'url' attribute is not specified` | 提前加了 `mybatis` / `flyway` / `mysql`，但没配数据源 | M01 先删掉这些依赖；或者直接按 M02 加 compose + `spring.datasource.*` |
| `Web server failed to start. Port 8080 was already in use` | 8080 被别的进程占用 | `lsof -nP -iTCP:8080 -sTCP:LISTEN` 找到并结束；或改 `server.port`，同步改 curl 端口 |
| `zsh: permission denied: ./mvnw` | 解压后丢了执行位 | `chmod +x mvnw` |
| `Unsupported class file major version` / 编译目标不对 | `JAVA_HOME` 指向了别的 JDK | `./mvnw -v` 看 Java 版本，按 §1 切到 21 |
| `GET /actuator/health` 404 | 没加 actuator，或 exposure 写错 | 查 `pom.xml` 是否有 `spring-boot-starter-actuator`；查 YAML 的 `management...include` |
| health 变 401 | 你后来自己声明了 `SecurityFilterChain`，没放行 health | 在链里加 `.requestMatchers("/actuator/health").permitAll()`（M05 会做） |
| `/tickets` 返回 401，不是 302 | curl 默认 `Accept: */*`，默认安全配置走 Basic | 这就是预期；要看 302 就加 `-H 'Accept: text/html'` |
| `smoke.sh --only=health` 失败 | 脚本第二条断言 `/tickets` 302，M01 是 401 | M01 不跑整脚本；等 M05 |
| `Cannot find template location: classpath:/templates/` | 还没建模板目录 | 预期内，M04 消失 |
| `No MyBatis mapper was found` | 提前加了 MyBatis starter | M01 不需要 MyBatis，删掉依赖；M03 再加 |
| 启动报 `mapping values are not allowed here`，位置指向 `spring:` | 第一行残留了 `spring.application.name=ticket`（properties 写法） | 用 §4 的 `cat >` 整份覆盖；第一行必须是 `spring:` |
| YAML 启动报 `ScannerException` / 缩进错误 | 用了 Tab 或冒号后没空格 | 重写 §4 的内容，统一两空格 |
| `./mvnw` 下载卡住 | 网络/代理 | 换网络；或临时用系统 `mvn` 验证，但提交前仍建议跑一次 `./mvnw` |
| `git commit` 报 `Author identity unknown` | 没配 Git 用户信息 | `git config --global user.name "你的名字"`；`git config --global user.email "you@example.com"` |

## 10. 下一步：M02

M02 才会把数据库接进来，顺序大致是：

1. 安装 Docker（或 OrbStack），`docker run --rm hello-world` 验证；
2. 写根目录 `compose.yaml`（MySQL 8.4），`docker compose up -d`，等 `healthy`；
3. 在 `pom.xml` 把 Initializr 的 `flyway` 依赖加回来（`spring-boot-starter-flyway`），再补 `flyway-mysql` 和 MySQL 驱动（MyBatis 留到 M03）；
4. 在 `application.yaml` 加 `spring.datasource.*` 与 Flyway 配置；
5. 写 `V1__init.sql`（7 张表）和 `V2__seed.sql`（org + 4 个分类）；
6. 用 `show tables` 验证 7 张表。

注意：接库之后，`/actuator/health` 会多一个数据库检查。MySQL 没起时整体状态会变 `DOWN`，这不是 M01 坏了，而是 M02 的第一道排障题。

M01 的 `HealthTest` 和提交都保留，M02 在此基础上加东西，不推翻。

## 11. 为什么和现有文档不一样

为了守住“M01 不依赖 Docker”这个门禁，本教程做了几处取舍，并已同步到 `04-progress.md`（下表“修改前”指同步前的原文）：

| 现有文档（修改前） | 原文 | 本教程 | 原因 |
| --- | --- | --- | --- |
| `03-build-guide.md` §1.1 | Initializr 依赖含 `flyway`、`mysql`、`testcontainers` | 去掉这三个 | 没有数据源时 JDBC 自动配置会让应用启动失败；Testcontainers 让测试依赖 Docker |
| `03-build-guide.md` §1.2–§1.3 | 补 MyBatis/Flyway、写 compose、配数据源 | 移到 M02（数据库）/ M03（MyBatis） | M01 只验证框架；数据库单独排障 |
| `04-progress.md` M01 | `application.yaml` 含数据源、MyBatis、Flyway | 只留应用名、端口、Actuator | 同上 |
| `04-progress.md` M01 | 做完跑 `smoke.sh --only=health` | 改为 health + `./mvnw test` | 脚本还断言 `/tickets` 302，M01 实际 401，M05 才成立 |
| `05-test-plan.md` M01 | T01-1、T01-2 | `HealthTest` + 日志检查 | 把手工验收变成可重复的测试 |

如果你更想按 `03-build-guide.md` 的 M1 一次做完（含数据库），那就不是 M01 了：把 §2 的 `flyway,mysql` 加回来，先完成 §10 的 1–4，再验健康检查。两条路都行，但**不要在半接状态**：要么不接库，要么库和配置都就绪。
